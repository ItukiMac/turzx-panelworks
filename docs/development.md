# 開発・検証と安全性

この文書はビルド、試験、変更時の規約と報告方法を扱います。内部設計は[アーキテクチャ](architecture.md)、実行後の操作は[利用ガイド](user-guide.md)を参照してください。

## ビルド環境と手順

Windows、.NET Framework 4.8、PowerShell 5.1以降が必要です。追加パッケージの取得は不要です。build/Build.ps1が.NET FrameworkのC#コンパイラを直接呼び出します。

コマンドはリポジトリのルートで実行してください。ビルドだけを行う場合は次を実行します。

```powershell
.\build\Build.ps1
```

## 生成物の配置

生成物はGit管理外のbin/へ、依存DLLはbin/lib/へ出力します。連番テンプレートはbin/layouts/へ生成します。生成元はsrc/Core/LayoutCatalog.csです。EXEと同名の.exe.configがDLLの検索先を指定します。配布・移動時はEXE、同名の設定ファイル、libフォルダーを一緒に扱ってください。

## 検証手順と範囲

次のコマンドはビルドも行うため、事前のビルド操作は不要です。

```powershell
.\build\Verify.ps1
```

USB機器を開かず、次を検証します。

- オフライン試験：数式、シーン、描画、RGB565変換、異なる画面の振り分け、グループ共有、同一画像の転送省略、負のストライドを持つ画像の変換、機器障害の隔離、停止・終了時のリソース寿命。
- WinFormsスモーク試験：フォームの構築、レイアウト、描画。ライブ計測やUSB列挙は開始しません。

テンプレートについては全分割・全表示項目の範囲、数式、XML保存・再読込、旧XML互換、既存テンプレートの保持を検証します。UI試験は簡易作成、元ファイルの保護、詳細編集の保存、AI用ファイルの書き出し・読み戻しも検証します。

複数機器のルーティングは偽機器で検証しています。複数実機の同時接続・表示試験は別途必要です。ソフトウェア上の送信完了だけで実画面の表示確認を代替しないでください。

## 画素変換ベンチマーク

ビルド後、必要に応じて次を実行します。

```powershell
.\bin\TurzxPanelWorks.OfflineTests.exe --benchmark
```

結果は画素変換部分だけの比較であり、アプリ全体の性能やUSB転送速度を保証するものではありません。

## 変更時の規約

1. 1つの変更は1つの目的に限定してください。
2. [アーキテクチャ](architecture.md)の責務分担と依存関係を維持してください。
3. 変更後は上記の検証を実行し、成功を確認してください。
4. 生成物、配布バイナリ、ログ、秘密情報、個人情報、実機固有ID、ローカル絶対パスをコミットしないでください。
5. 外部コードや素材を追加する場合は、出典、バージョン、ライセンスを[第三者の著作権・ライセンス表示](THIRD_PARTY_NOTICES.md)へ記録してください。

プルリクエストには目的、変更範囲、検証結果、安全性への影響を記載してください。

新規コードにはSPDX-License-Identifier: GPL-3.0-or-laterを付け、GPL-3.0-or-laterで提供可能なコードだけを提出してください。参照・翻案した部分は元の著作権表示を保持し、変更を明記してください。

## テンプレートの見た目を確認する

ビルド後、次のコマンドでダミー値のプレビューと6案の一覧画像を作成できます。

```powershell
.\bin\TurzxPanelWorks.OfflineTests.exe --render-templates .\bin\layouts\previews
```

生成元を変更しても既存のテンプレートXMLは上書きされません。変更した生成結果は新しい出力環境で検証し、既存利用者のカスタマイズを保持してください。

## オンライン表示の検証

通常のVerifyはネットワークやブラウザーを起動しません。カレンダーのうるう年・6週表示、天気JSONの欠損値、URL制限、白紙画像の判定はオフラインで検証します。

接続先を実際に確認する場合だけ、次を実行します。東京のOpen-Meteo予報とYahoo!ニュースへ接続し、結果画像を保存します。USB機器は開きません。

```powershell
.\bin\TurzxPanelWorks.OfflineTests.exe --online-widgets .\bin\layouts\previews
```

オンライン試験はサービス側の応答やブラウザーの導入状態に依存します。画像が生成された場合も、エラーページや同意画面でないことを目視確認してください。

## 自動テストの範囲

`build/Verify.ps1` は24グループのオフラインテストとWinFormsスモークテストを実行します。グループ単位で結果を表示し、例外のあるグループも失敗として記録します。試験ごとの一時ファイルはプロジェクトのbin内に作成して終了時に削除します。各試験実行ファイルは60秒で打ち切ります。

| 対象 | 自動確認 |
| --- | --- |
| シーン・設定 | 保存と復元、旧形式、破損XML・DTD・不正設定値の拒否、ファイル変更の再読込、不正編集時の停止と修正後の復帰 |
| レイアウト・描画 | テンプレート、指標と数式、回転、RGB565、カレンダーのうるう日・6週目の位置 |
| 外部表示 | 天気JSON、URL制限、白紙判定、オンラインOFF、取得中の描画と重複抑制、更新間隔、失敗時の再試行、破棄時のキャンセル |
| 配信 | ダミー機器での更新・機器別フレーム・例外後の後始末・多重実行・終了・共有テレメトリの寿命、不正送信データの書込み防止 |
| 画面 | Editor/Hostの構築と描画、タブ配置、かんたん編集・詳細保存・AI出力・外部表示設定、単一起動、トレイ |

外部表示の非同期試験は取得関数と時計を差し替え、ネットワークなしで実行します。ソースは`tests/OfflineTests/Program.cs`、追加の境界・異常系は`RegressionTests.cs`、画面試験は`tests/WinFormsSmoke/Program.cs`です。ファイル数はテスト件数を表しません。

実機USBの接続／切断、複数の実機への同時表示、Windowsの実測値の正確さ、ブラウザーの実プロセス終了、サイトの同意画面や構成変更、DPI別の操作感はこの自動試験では保証しません。外部サービスは上記オンライン試験と目視確認、機器依存の動作は実機試験が必要です。網羅率100%を示すものではありません。

ニュースは `bin/TurzxPanelWorks.OfflineTests.exe --news-preview bin/layouts/previews` で実RSSの連続3カードを画像化できます。通常試験にはRSS解析・循環境界・取得失敗時の見出し維持・再試行と、Hostの停止中の選択直後プレビュー更新（USB接続なし）を含みます。アプリ使用中の別出力検証は `build/Verify.ps1 -OutputDirectory <プロジェクト内の出力先>` を使用できます。

更新間隔の試験はTimingTests.csにあります。6項目の保存・旧設定の既定値・境界、描画なしでのハードウェア取得、取得の重複防止と終了待機、取得時刻と時計の分離、ニュース／天気／サイトのHost指定間隔、RSS再取得時のカード進行維持を検証します。画面試験では選択XMLに応じた入力欄の切替、ラベル・範囲・既定値の読込、XMLだけで追加した数値設定の表示と保存を確認します。HostParameterTests.csでは汎用設定の描画反映、元XMLの保持、旧形式と空定義の区別を検証します。


## レイアウトXMLでHost設定を定義する

`DashboardScene` 直下の `HostParameters` に、Hostで変更したい数値を定義します。新しいXMLは保存時に必要な標準項目を補完します。既に定義があるXMLはそれを保持します。例はニュースのカード切替と幅です。画面送信なども公開する場合は、既存の定義を残して追記してください。

```xml
<HostParameters>
  <Parameter Key="news.slide" Label="ニュース切替" Unit="秒"
             Target="kind:News" Property="SlideSeconds"
             Minimum="3" Maximum="300" Step="1" Decimals="0"
             Value="10" Scale="1" />
  <Parameter Key="card.width" Label="カード幅" Unit="px"
             Target="kind:News" Property="Width"
             Minimum="100" Maximum="456" Step="1" Decimals="0"
             Value="456" Scale="1" />
</HostParameters>
```

- `Key` は保存値の識別子です。同じキーはレイアウト間で値を共有するため、独立させる設定には別のキーを付けます。キーの単位や意味を変える場合も新しいキーにします。
- `Label`、`Unit`、`Minimum`、`Maximum`、`Step`、`Decimals` が入力欄の表示を決め、`Value` が既定値になります。定義は最大64項目です。
- `Target="kind:News"` はその種類の全要素、`Target="id:要素ID"` は特定要素に適用します。対象がない項目は非表示です。
- `Property` はSceneElementの公開数値プロパティです。既存プロパティの公開項目を増やすだけならHost UIの改修は不要です。新しい表示方式・新しいデータ取得処理そのものは描画側等への実装が必要です。
- 実際のプロパティ値は入力値×`Scale` です。`Target="Host" Property="IntervalMilliseconds"` または `HardwareIntervalMilliseconds` を秒単位で表示する場合は、`Scale="1000"`、`Minimum="0.25"`、`Maximum="60"`、`Step="0.25"`、`Decimals="2"` とします。
- 定義自体はXMLに保存し、ユーザーが変更した値はHost設定の `ParameterValues` に保存します。元のレイアウトは変更しません。「XMLの既定値へ」で表示中の項目をリセットできます。
- 定義を省略した旧XMLは要素と数式から互換補完します。空の `<HostParameters />` は何も公開しません。不正な範囲、重複キー・設定先、数値以外のバインディングは拒否します。

既存の同梱テンプレートへ未定義の設定メタデータだけを追加する場合は、`bin/TurzxPanelWorks.OfflineTests.exe --upgrade-template-parameters bin/layouts` を明示的に実行します。既に定義があるファイルは変更しません。

# TURZX PanelWorks 利用ガイド

コマンドはリポジトリのルートで実行してください。

TURZX製ディスプレイ向けの非公式・独立開発ツールです。メーカーによる公式提供、公認、提携を示すものではありません。Editorで画面を編集し、Hostで継続表示を管理します。

Windowsでダッシュボードを編集し、複数のRev A USBモニタへそれぞれ異なる画面を表示するアプリケーションです。

## 利用の準備

ソースから実行ファイルを作成する手順は、[開発ガイド](development.md)を参照してください。以下の起動例はビルド済みの状態を前提とします。

## 連番テンプレートを選ぶ

EditorとHostは、引数なしで起動すると実行ファイルと同じ場所の `layouts/01-clock-system-overview.scene.xml` を参照します。通常のビルドでは `bin/layouts/` です。テンプレートはビルド時と起動時に不足分だけ生成し、既存のファイルは上書きしません。

| 番号 | ファイル名 | 内容 |
| --- | --- | --- |
| 01 | `01-clock-system-overview.scene.xml` | 作成済みDefaultを整形した総合表示。時計・曜日付き日付、CPU・GPU・RAM、音量・送受信・ディスク |
| 02 | `02-clock-cpu-gpu-ram.scene.xml` | 時計とCPU・GPU・RAMのカード |
| 03 | `03-cpu-gpu-ram-disk-grid.scene.xml` | CPU・GPU・RAM・ディスクの4分割 |
| 04 | `04-system-network-grid.scene.xml` | CPU・GPU・RAM・ディスク・送受信の6分割 |
| 05 | `05-cpu-gpu-comparison.scene.xml` | CPU・GPUの左右比較 |
| 06 | `06-clock-weather-calendar.scene.xml` | 時計・東京天気・カレンダー |
| 07 | `07-yahoo-news-carousel.scene.xml` | Yahoo!ニュースの循環カード |

各数値にタイトルのText要素を付けています。CPU・GPUには温度、RAMには使用容量も表示します。未取得の温度は `--` になります。

「かんたん」タブで番号を選ぶと、すぐにテンプレートを開いて表示します。コピーは未保存状態で開くため、「レイアウト」タブから別名で保存してください。「レイアウト」のファイル一覧でも番号順に選べます。既存のXMLは「ファイルを開く」または起動引数で引き続き利用できます。

## 大まかな配置を決める

1. 「かんたん」タブで、時計＋3ブロック・左右2分割・4分割・6分割のいずれかを選びます。
2. 各ブロックにCPU・GPU・RAM・DISK・UPLOAD・DOWNLOAD・CLOCK・空白・カレンダー・天気・サイトのどれを表示するか選びます。番号は左上から右へ、次に下の段へ進みます。
3. 「この内容で新規作成」を押すと、タイトル・数値・補助情報・バーやグラフをまとめて配置します。
4. 「レイアウト」タブで名前を付けて保存します。保存先の初期値は `bin/layouts/` です。外部ファイルを開いている場合は、そのファイルと同じフォルダーを使用します。

分割設定の選択中は現在の画面を保持し、「新規作成」で反映します。作成結果は別の未保存レイアウトになり、元ファイルは変更しません。詳細編集後に再作成すると、その微調整は引き継がずブロックから再生成します。残したい内容は先に保存してください。

## 詳細を編集する

```powershell
.\bin\TurzxPanelWorks.Editor.exe layout-a.xml
```

「詳細」タブで従来どおりドラッグ、座標、サイズ、文字サイズ、配置、数式を変更できます。Text、Bar、Graph、Rectangleを編集し、モニタごとのレイアウトを別のXMLに保存します。Editorのプレビュー更新間隔は0.25〜60秒で設定でき、最小化中は自動プレビュー更新を休止します。EditorにはUSB送信機能はありません。

## カレンダー・天気・サイトを表示する

「かんたん」で05または06を選ぶだけで表示します。オンライン情報は自動取得し、通信中は取得状態を表示します。既存のレイアウトにも、分割ブロックの項目選択、または「外部表示」タブの追加ボタンから組み込めます。配置とサイズは「詳細」で変更してください。

カレンダーはPCの日付に合わせた月間表示で、当日を強調します。祝日判定や個人の予定表との同期は含みません。

天気は東京（緯度35.681、経度139.767）を初期値とし、3日分の天候・最高/最低気温・降水確率を表示します。「外部表示」で天気の要素を選択すると、地域名と緯度・経度を変更できます。予報の日付は日本時間です。狭いブロックでは降水確率などの補助情報を省略します。

Editorではテンプレート選択時にオンライン取得が自動でONになります。「外部表示」のチェックで停止もできます。Hostはレイアウト・背景・回転・選択行を変更するとプレビューをすぐ更新し、停止中も1秒ごとに描画します。USB送信の開始や送信間隔とは独立しています。

既定の取得間隔は10分で、1〜1440分へ変更できます。取得処理は描画とは別に進み、完了後の次の画面更新で反映します。失敗時は「更新失敗」と最終成功日時を表示し、取得済み画像・予報を残します。再試行は最短1分後です。初回未取得と古い取得済み情報は区別して表示します。

天気の取得元は[Open-Meteo](https://open-meteo.com/en/docs)です。このサンプルは個人利用向けの無料APIを使用します。提供条件は[公式利用条件](https://open-meteo.com/en/terms)を参照してください。

### 指定サイトの設定

06はYahoo!ニュースの主要トピックスRSSを読み、見出し・掲載時刻・出典・順番をカード表示します。既定で10秒ごとに次の見出しへ進み、最後から先頭へ戻ります。「外部表示」のニュース要素でカード切替を3〜300秒、取得間隔を1〜1440分に設定できます。取得失敗時は前回の見出しを残して失敗状態を表示し、1分後に再試行します。初回の取得にはネット接続が必要です。記事本文や写真は転載しません。

一般のWebページ画像を表示する場合は「サイト」要素を追加します。「外部表示」でサイト要素を選び、URLと表示幅を入力して「選択要素に設定を反映」を押し、レイアウトを保存します。表示幅は320〜1920pxで、取得画像をブロック内へ縮小します。小さい幅は文字を大きく表示しやすく、大きい幅はサイト全体の構成を確認しやすくなります。

サイト表示にはインストール済みのGoogle ChromeまたはMicrosoft Edgeを使用します。ページ上部の画像を定期取得する閲覧専用機能で、モニタ側でリンクのクリックやスクロール操作はできません。ログインや同意操作が必要なページでは、その画面が表示される場合があります。

通常のブラウザープロファイルは使用しません。取得専用の一時プロファイルを `bin/cache/web/` に作り、取得終了後に専用ブラウザーを終了して削除します。ロック等で削除できない一時ファイルは残る場合があります。白紙やタイムアウト時は取得失敗として表示します。サイト固有のレイアウトや配信条件により、すべてのURLの表示を保証するものではありません。
## ChatGPT・Copilotなどに微調整を依頼する

「かんたん」タブの「AI調整用セットを書き出す」で保存先を選びます。毎回別のサブフォルダーを作成し、次の3ファイルを出力します。

- `layout.scene.xml`：未保存の変更を含む現在のレイアウト。
- `preview.png`：ダミー値と現在の背景による480×320の完成イメージ。選択枠は含みません。
- `調整ガイド.txt`：座標・色・数式・利用可能な数値項目、希望する変更を書き込む依頼文、読み戻し手順。

3ファイルをAIに添付し、希望の配色・余白・文字サイズ・設置方向を伝えてください。背景自体を調整する場合は元画像も添付します。書き出した画像には現在の背景が含まれるため、共有前に内容を確認してください。アプリからAIへ自動送信する機能ではなく、サービス固有の連携設定も不要です。

天気の地域・座標とサイトURLもXMLに含まれます。AI用プレビューではオンライン取得を行いません。外部情報を含む実表示も渡したい場合は、オンライン取得後に「Save PNG」で保存した画像を添付してください。

返されたXMLは別名の `.scene.xml` として `bin/layouts/` に保存し、「レイアウト」→「ファイルを開く」で読み込みます。プレビューで確認してからHostへ割り当ててください。Hostの機器別回転や背景ファイルの設定はXMLに含まれないため、別途指定します。
## モニタごとに割り当てる

```powershell
.\bin\TurzxPanelWorks.Host.exe layout-a.xml
```

1. 「機器一覧」で接続済みモニタを列挙します。
2. 行を選んで「レイアウト選択」「背景選択」から、そのモニタのXMLと任意の画像を指定します。背景未指定なら無地になります。
3. 「回転(°)」列で時計回りの0・90・180・270度を選び、送信する行にチェックを付けます。例：モニタAにCPU/RAM画面、モニタBに時計/ネットワーク画面を割り当てられます。
4. 「1回更新」または「更新開始」を押します。「停止・切断」で更新と接続を終了します。

回転はモニタごとに保存され、次回起動時に復元されます。旧設定の既定値は0度です。回転は背景を含む描画画像全体へ適用します。USB出力は480×320固定のため、90・270度では縦横比を維持して縮小し、左右に黒い余白を付けます（縦画面用レイアウトへの自動再配置や機器の方向設定変更は行いません）。角度変更は「停止・切断」後に行ってください。

選択中の行を左側に常に正立（上が上）の状態でプレビューします。送信チェックのない行も確認できます。0・180度は横長、90・270度は縦長の縦横比で表示します。プレビューの正立表示はUSB送信画像の回転設定に影響しません。対象なしではプレビューだけを更新します。開始中の割当変更は停止後に行ってください。

### XMLから読み込むHostの表示設定

「表示設定（レイアウトXML）」には、選択中のXMLの `HostParameters` に定義された数値設定だけが表示されます。項目名、単位、範囲、刻み、既定値をXMLから読み込みます。ニュース専用テンプレートでは画面送信・ニュース取得・ニュース切替、CPU等のテンプレートでは画面送信・ハードウェア取得が表示されます。対応する要素がない項目は表示しません。

同じ `Key` の変更値はHost内で共有され、終了時に保存・次回起動時に復元されます。XMLの `Value` は初期値です。変更済みの値を初期値に戻すには「XMLの既定値へ」を押します。以下は同梱テンプレートが定義する項目の一覧で、固定の6項目を常に表示する方式ではありません。

| 設定 | 既定値 | 範囲 | 対象 |
| --- | --- | --- | --- |
| 画面送信（秒） | 1秒 | 0.25〜60秒 | 描画した画像をUSB機器へ送る間隔 |
| ハードウェア取得（秒） | 1秒 | 0.25〜60秒 | CPU・GPU・メモリ・ネットワーク・センサー等の値を取り直す間隔 |
| ニュース取得（分） | 10分 | 1〜1440分 | Yahoo!ニュース等のRSSを取り直す間隔 |
| ニュース切替（秒） | 10秒 | 3〜300秒 | 取得済みニュースの次のカードへ進む間隔 |
| 天気取得（分） | 10分 | 1〜1440分 | 天気予報を取り直す間隔 |
| サイト画像取得（分） | 10分 | 1〜1440分 | 一般サイトの画像を取り直す間隔 |

HostはXMLの設定定義に従って描画用のコピーへ値を適用し、XML自体は変更しません。Editorのプレビューには引き続き要素自身の設定を使います。定義のない旧XMLは要素の種類・数式から設定を補完します。明示的な空の `<HostParameters />` は「項目なし」と扱います。旧Host設定の6つの間隔値も読み込めます。

画面送信は1周期の処理完了後に指定時間待機するため、実際の周期は処理時間＋待機時間です。ハードウェア取得は専用の処理で行い、描画時には最後に取得した値を使用します。時間のかかる取得を重ねて実行せず、処理時間が設定間隔を超えた場合は完了後に次の取得へ進みます。時計・カレンダー・ニュースの進行はハードウェア取得時刻から独立しています。

プレビューと外部情報の取得開始条件は約1秒ごとに確認します。送信中は選択行以外の送信対象も確認し、最小化中も継続します。新しい情報や切り替わったカードが実機に表示されるのは次の画面送信時です。たとえば画面送信が30秒、ニュース切替が10秒の場合、実機には30秒ごとのカードが表示されます。ニュースの再取得でカードの循環を先頭に戻しません。

Hostの間隔と機器別XML/背景割当は、ユーザーのローカルアプリデータ内に保存します。起動時に自動送信はしません。ローカル設定には機器識別子とファイルパスが含まれるため、共有・コミットしないでください。

## 対応範囲と制約

対応範囲はRev A・480×320であり、TURZXシリーズ全機種への対応を意味しません。

機器エラーはその機器を停止状態に保持し、自動再接続しません。「停止・切断」後に明示的に再開できます。停止・終了は進行中処理の完了またはタイムアウトを待ちます。機器の検出や接続にかかる時間によっては、停止・終了まで30秒を超える場合があります。

音量取得は未実装で0を返します。温度など取得できない値は未取得扱いです。機器のファームウェア更新、リセット、ドライバー導入は実装していません。ソフトウェア上の送信完了と、実画面の目視確認は別です。検証済みの範囲は[開発ガイド](development.md)を参照してください。

## 名称変更と既存設定

旧名称はStandalone Displayです。実行ファイル名はTurzxPanelWorks.Editor.exe／TurzxPanelWorks.Host.exeに変更しました。既存設定を引き継ぐため、ローカル設定の保存先フォルダー名StandaloneDisplayは維持しています。

## ウィンドウと常駐動作

EditorとHostには専用のアプリアイコンを設定しています。Hostを最小化するとタスクトレイへ格納され、更新中の表示処理は継続します。トレイアイコンのダブルクリック、または右クリックメニューの「開く」で復帰します。「終了」またはウィンドウの閉じるボタンは、実行中の更新終了を待って接続を閉じ、設定を保存して終了します。

同じWindowsユーザー・セッションではEditorとHostをそれぞれ1つだけ起動できます。再起動操作は既存の画面を復帰させ、新しいプロセスは終了します。EditorとHostの同時利用は可能です。二重起動時のファイル引数は既存画面へ適用しません。レイアウトの切替は既存画面から行ってください。



## 株価・為替を選ぶ

Editorの「株価・為替」タブで銘柄・通貨ペアを選び「この銘柄を追加」を押します。日本株（7203.T、6758.T、9984.T、7974.T）、米国株（AAPL、MSFTなど）、通貨ペア（USD/JPY、EUR/JPYなど）のプリセットと、コードの直接入力に対応します。日本株の4桁コードには自動で `.T` を付けます。

Yahoo!ファイナンスの公開ページをブラウザーで描画して表示します。APIへの接続やAPIキー登録は不要です。チャート領域を画面に収め、銘柄コードと掲載元を添えて表示します。期間・足種は掲載元の初期設定です。情報の内容・遅延は掲載元に準じます。数値を抽出する独自カードではなく、公開チャートの画像です。ページの構成変更やアクセス制限によって表示できなくなる場合があります。

既存の表示は同じタブの一覧から選び、コードと取得間隔を変更して「選択した表示を変更」を押します。配置・サイズは「詳細」で調整し、レイアウトを保存してください。1要素につき1銘柄です。

Editorでは「外部表示」のオンライン取得をONにします。Hostは外部情報を取得します。既定の取得間隔は15分で、Host側の「株価・為替取得」設定でも変更できます。Microsoft EdgeまたはGoogle Chromeが必要です。取得失敗時には前回画像と更新失敗の状態を表示します。旧API方式で保存したMarket要素も同じ銘柄コードから公開ページに切り替わります。以前のキー保存ファイルは読み込みません。
